## Before submitting

- Fill in the registered team name, member names and contributions in the submission form. Do not invent these.
- The supplied form confirms **AI and Developer Tools → Problem Selection → Why The Code Is Like This**. Confirm any additional Neo4j prize/track selection in the portal.
- The supplied form requires a PDF/PPTX presentation (25 MB maximum), source archive (50 MB maximum) and public GitHub URL. Video (MP4/MOV, 25 MB maximum) has no visible required asterisk. Check any additional portal instructions and undisplayed character limits.
- Record and upload the actual demo video; add its accessible link to the submission. No video has been recorded by preparing this kit.
- Verify repository access in a signed-out browser and include setup instructions. The supplied submission form explicitly requires a public repository URL.
- Rehearse the deployed guest flow, OAuth login, saved work and deletion. Deployment logs confirm startup, not acceptance of every feature.
- Do not include credentials, private repository excerpts or personal account details in recordings.
- Review and personalize the AI assistance disclosure in the submission copy.

## Event guidance used

[HackFront India event page](https://whereuelevate.com/drills/hackfrontindia-2026) lists problem/track alignment, innovation, technical implementation, functionality and practical reasoning as evaluation criteria. It also requires disclosure of AI tools, open-source frameworks and third-party APIs used in the project.

The page checked on 31 October lists prototype submission closing on 31 October 2026 at 6:29 PM IST. Confirm the deadline in your signed-in portal; event information can change. The three-minute video plan and six-slide outline here are preparation formats, not verified mandatory event formats.

## Demo constraints to explain honestly

The app is deployed on Render Free and may take time to start after inactivity. Custom SMTP has been deferred, so public email signup and recovery delivery are not ready for arbitrary recipients. Use guest exploration or configured Google/GitHub login for judging. OAuth audience/test-user restrictions, if still enabled in a provider dashboard, must also permit the judges.

Do not claim measured onboarding savings, perfect factual accuracy, full-repository coverage, production load validation or independent security certification. None is established by this kit.
